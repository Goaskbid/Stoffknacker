Datenmodellierung

Man legt fest, welche Objekte mit welchen Eigenschaften gespeichert werden und wie sie zusammenhängen, bevor Tabellen entstehen.

Arbeite mit einem kleinen Beispiel, formuliere den Ablauf eindeutig und prüfe ihn mit Gegenfällen.

Tabellen

Jede Zeile einer Tabelle ist ein Objekt. Ein Primärschlüssel identifiziert sie eindeutig, ein Fremdschlüssel verweist auf eine Zeile einer anderen Tabelle.

Ein Fremdschlüssel verlangt, dass ein eingetragener Wert zu einem zulässigen Schlüssel der referenzierten Tabelle passt. Das kann deren Primärschlüssel oder ein geeigneter eindeutiger Schlüssel sein. Auch ein Verweis innerhalb derselben Tabelle ist möglich, etwa von einer Person auf ihre Vorgesetzte. Solche Regeln müssen im Datenbanksystem eingerichtet und wirksam sein.

Abfragen

In SQL wählt SELECT Spalten, WHERE filtert Zeilen und JOIN verbindet Tabellen über ihre Schlüssel.

Ein Beispiel: SELECT Name FROM Schueler WHERE Klasse = '3a' liefert alle Namen der Klasse 3a. Mit JOIN lassen sich etwa Noten und Namen aus zwei Tabellen verbinden.

Anwendung, Transfer

Zum Abschluss überträgst du die drei Kernbereiche auf eine neue Situation. Eine gute Lösung nennt Ausgangslage, Vorgehen, Ergebnis und Kontrolle.

Entwirf eine kleine digitale Lösung und begründe Datenmodell, Ablauf, Tests und Schutzmassnahmen. Die Begründung muss zeigen, warum das Vorgehen zur Frage passt.

Genauer betrachtet

Ein Primärschlüssel identifiziert einen Datensatz eindeutig. Ein Fremdschlüssel beschreibt eine referenzielle Bedingung: Der gespeicherte Verweis muss zu einem erlaubten Schlüssel passen. In geeigneten Datenbanksystemen kann dies neben einem Primärschlüssel auch ein eindeutiger anderer Schlüssel sein.

Ein Fremdschlüssel kann auch innerhalb derselben Tabelle liegen, etwa bei der ID einer vorgesetzten Person. Die Aussage immer andere Tabelle ist deshalb zu eng. Ob Löschen oder Ändern erlaubt ist, bestimmen die festgelegten Aktionen und weitere Bedingungen.

Eine deklarierte Regel muss tatsächlich aktiv sein. Bei SQLite ist die Fremdschlüsselprüfung für die verwendete Verbindung ausdrücklich zu aktivieren und zu kontrollieren. Ein Kommentar im Programm ersetzt die wirksame Datenbankbedingung nicht.

Durchgerechnete Beispiele

Datenbanken und Abfragen

Aufgabe: Fiktive lokale Datenbank: Personen p1 und p2; Ausleihen a1 für p1, a2 für p1 und a3 für p2. Gesucht sind die Anzahl Ausleihen und die Anzahl unterschiedlicher ausleihender Personen. Anschliessend wird eine Ausleihe für die nicht vorhandene Person p9 versucht.

  1. Die Personentabelle hat zwei Zeilen und die Ausleihtabelle drei. Eine Verknüpfung über person_id kann p1 daher zweimal liefern. Das ist keine versehentliche Verdopplung der Personentabelle, sondern eine Eins-zu-viele-Beziehung.
  2. COUNT(*) über die Ausleihtabelle ergibt 3. COUNT(DISTINCT person_id) ergibt 2. Beide Abfragen sind korrekt, beantworten aber andere Fragen.
  3. Aktiviere die Fremdschlüsselprüfung und füge person_id = p9 ein. Weil p9 in der referenzierten Tabelle fehlt, muss die vorgesehene Integritätsprüfung scheitern.
  4. Prüfe nach dem abgefangenen Fehler, dass keine ungültige Ausleihe gespeichert wurde. Fehlerbehandlung darf nicht versehentlich Erfolg anzeigen.

Ergebnis: Es gibt drei Ausleihen von zwei unterschiedlichen Personen. Der Verweis auf p9 wird abgewiesen, wenn die Bedingung wirksam eingerichtet ist. Kontrolle: Der beigefügte Python-/SQLite-Test läuft nur in einer temporären In-Memory-Datenbank. Er kontrolliert PRAGMA, beide Zähler und den erwarteten Integritätsfehler.

Grenzen: Das Modell enthält weder echte Namen noch Nutzungsdaten. Normalisierung und Fremdschlüssel ersetzen keine Berechtigungen, Sicherung oder Datenschutzplanung.

Python-Beispiel zum Ausprobieren:

import sqlite3
db = sqlite3.connect(':memory:')
db.execute('PRAGMA foreign_keys=ON')
db.executescript('CREATE TABLE person(id TEXT PRIMARY KEY); CREATE TABLE loan(id TEXT PRIMARY KEY, person_id TEXT NOT NULL REFERENCES person(id));')
db.executemany('INSERT INTO person VALUES (?)', [('p1',), ('p2',)])
db.executemany('INSERT INTO loan VALUES (?,?)', [('a1','p1'),('a2','p1'),('a3','p2')])
assert db.execute('SELECT COUNT(*), COUNT(DISTINCT person_id) FROM loan').fetchone() == (3,2)
try:
    db.execute('INSERT INTO loan VALUES (?,?)', ('a4','p9'))
except sqlite3.IntegrityError:
    pass
else:
    raise AssertionError('missing foreign-key enforcement')
assert db.execute('SELECT COUNT(*) FROM loan').fetchone()[0] == 3
db.close()

Verständnis prüfen

Offene Fragen mit Musterantwort. Es gibt keine automatische Bewertung.

Warum ergibt ein Join drei Zeilen, obwohl nur zwei Personen existieren?

Weil p1 zwei Ausleihen hat. Jede passende Kombination wird als Ergebniszeile dargestellt.

Ist ein Fremdschlüssel zwingend ein Verweis auf einen Primärschlüssel einer anderen Tabelle?

Nein Geeignete eindeutige Schlüssel und Selbstreferenzen sind möglich, abhängig von den Regeln des Datenbanksystems.

Was ist ein sinnvoller Negativtest?

Ein Verweis auf eine nicht vorhandene Person. Der Test muss feststellen, dass die Operation scheitert und kein ungültiger Datensatz entsteht.

Typischer Fehler

Eine plausible Ausgabe beweist noch nicht, dass ein Algorithmus für alle Fälle korrekt ist.
