Datenmodellierung

Man legt fest, welche Objekte mit welchen Eigenschaften gespeichert werden und wie sie zusammenhängen, bevor Tabellen entstehen.

Arbeite mit einem kleinen Beispiel, formuliere den Ablauf eindeutig und prüfe ihn mit Gegenfällen.

Tabellen

Jede Zeile einer Tabelle ist ein Objekt. Ein Primärschlüssel identifiziert sie eindeutig, ein Fremdschlüssel verweist auf eine Zeile einer anderen Tabelle.

Ein Fremdschlüssel verweist auf den Primärschlüssel einer anderen Tabelle, etwa die Klassennummer in der Schülertabelle. So lassen sich Daten ohne Doppelungen verknüpfen.

Abfragen

In SQL wählt SELECT Spalten, WHERE filtert Zeilen und JOIN verbindet Tabellen über ihre Schlüssel.

Ein Beispiel: SELECT Name FROM Schueler WHERE Klasse = '3a' liefert alle Namen der Klasse 3a. Mit JOIN lassen sich etwa Noten und Namen aus zwei Tabellen verbinden.

Anwendung, Transfer

Zum Abschluss überträgst du die drei Kernbereiche auf eine neue Situation. Eine gute Lösung nennt Ausgangslage, Vorgehen, Ergebnis und Kontrolle.

Entwirf eine kleine digitale Lösung und begründe Datenmodell, Ablauf, Tests und Schutzmassnahmen. Die Begründung muss zeigen, warum das Vorgehen zur Frage passt.

Durchgerechnete Beispiele

Anwendung

Aufgabe: Entwirf eine kleine digitale Lösung und begründe Datenmodell, Ablauf, Tests und Schutzmassnahmen.

  1. Klären: Datenmodellierung
  2. Anwenden: Tabellen und Beziehungen
  3. Einbeziehen: Datenbankabfragen
  4. Kontrollieren: Ergebnis und Begründung

Ergebnis: Eine nachvollziehbare, kontrollierte Lösung.

Transfer

Aufgabe: Übertrage das Kernprinzip aus «Datenbanken und Abfragen» auf eine neue Situation und nenne eine Grenze der Übertragung.

  1. Situation strukturieren
  2. Gemeinsame Merkmale bestimmen
  3. Unterschiede markieren
  4. Schlussfolgerung begrenzen

Ergebnis: Ein begründeter Transfer mit klarer Grenze.

Typischer Fehler

Eine plausible Ausgabe beweist noch nicht, dass ein Algorithmus für alle Fälle korrekt ist.
