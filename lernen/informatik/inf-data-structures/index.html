Worum es geht

In einer Gruppe heissen zwei Personen Alex. Ein Wörterbuch mit dem Vornamen als Schlüssel ersetzt beim zweiten Alex den ersten Eintrag. Das Programm kann technisch korrekt arbeiten und trotzdem Informationen verlieren, weil das Datenmodell einen unpassenden Schlüssel verwendet.

Der Kern

Merke: Die richtige Datenstruktur macht ein Programm einfacher und schneller.

Wozu: Du wählst passende Strukturen und baust Programme aus kleinen, verständlichen Teilen.

Begriffe

Listen und ZuordnungenEine Liste speichert Elemente in einer definierten Reihenfolge und ermöglicht den Zugriff über Positionen. Bei einer veränderbaren Liste kann sich diese Reihenfolge durch Einfügen, Entfernen oder Sortieren ändern. Ein Wörterbuch ordnet dagegen eindeutigen Schlüsseln Werte zu. Welche Eigenschaften gelten, hängt auch von der verwendeten Sprache und Datenstruktur ab.

Listen

Eine Liste speichert Werte in fester Reihenfolge mit Index. Eine Zuordnung, auch Wörterbuch genannt, verknüpft Schlüssel mit Werten.

Arbeite mit einem kleinen Beispiel, formuliere den Ablauf eindeutig und prüfe ihn mit Gegenfällen.

Funktionen

Eine Funktion bündelt Anweisungen unter einem Namen, nimmt Parameter entgegen und gibt ein Ergebnis zurück. Sie macht Code wiederverwendbar und einzeln testbar.

Ein Beispiel: Eine Funktion Flaeche(Breite, Hoehe) gibt das Produkt der beiden Werte zurück. So lässt sich dieselbe Berechnung an vielen Stellen verwenden.

Abstraktion

Abstraktion blendet Details aus, die für die aktuelle Aufgabe unwichtig sind. Wer eine Funktion aufruft, muss wissen, was sie tut, nicht wie.

Ein Vergleich ist die Fernbedienung: Man drückt eine Taste, ohne die Elektronik dahinter zu kennen. Genauso erleichtert Abstraktion die Arbeit an grossen Programmen.

Anwendung, Transfer

Zum Abschluss überträgst du die drei Kernbereiche auf eine neue Situation. Eine gute Lösung nennt Ausgangslage, Vorgehen, Ergebnis und Kontrolle.

Entwirf eine kleine digitale Lösung und begründe Datenmodell, Ablauf, Tests und Schutzmassnahmen. Die Begründung muss zeigen, warum das Vorgehen zur Frage passt.

Genauer betrachtet

Eine Liste ordnet Elemente nach Position. Ein Wörterbuch ordnet eindeutigen Schlüsseln Werte zu. Ob ein Merkmal als Schlüssel geeignet ist, ist keine reine Syntaxfrage. Ein Vorname ist in diesem Fall gerade nicht eindeutig.

Stabile Identifikatoren trennen die technische Identität von veränderlichen Anzeigenamen. Ein Name kann korrigiert werden, ohne dass der Datensatz eine neue Identität bekommt. Derselbe Grundsatz hilft später bei Datenbanken und beim Erhalt von Lernfortschritt.

Eine Funktion braucht ausserdem klare Wirkungsregeln. Soll sie die Eingabe verändern oder einen neuen Index erzeugen? Im Lehrbeispiel erzeugen wir einen neuen Index und weisen doppelte IDs ausdrücklich zurück, statt einen Datensatz still zu überschreiben.

Durchgerechnete Beispiele

Datenstrukturen und Modularisierung

Aufgabe: Fiktive Datensätze: p1, Alex, 12 Punkte; p2, Alex, 15 Punkte; p3, Sam, 9 Punkte. Gesucht ist ein Index nach ID und danach eine Zuordnung von Namen zu allen dazugehörigen IDs. Die Namen sind reine Beispielnamen.

  1. Beim Index nach ID entstehen drei Schlüssel: p1, p2, p3. Beide Alex-Datensätze bleiben erhalten.
  2. Ein direkter Index nach Name mit nur einem Wert pro Schlüssel hätte dagegen nur Alex und Sam. Der zweite Alex würde den ersten ersetzen, sofern keine besondere Prüfung existiert.
  3. Für die Namenssuche verwende eine Liste von IDs pro Name: Alex verweist auf [p1, p2], Sam auf [p3]. Jetzt entspricht die Datenstruktur der fachlichen Mehrdeutigkeit.
  4. Ergänze einen Test mit einer doppelten ID p1. Die Funktion bricht mit einer begründeten Fehlermeldung ab, bevor sie eine erfolgreiche Vollständigkeit suggeriert.

Ergebnis: Drei Personen brauchen hier drei eindeutige IDs. Der Anzeigename darf mehrfach vorkommen und ist deshalb kein geeigneter alleiniger Primärschlüssel. Kontrolle: Vergleiche die Zahl der Eingabedatensätze mit der Zahl eindeutiger IDs. Teste Namen mit Duplikaten bewusst, nicht nur drei verschiedene Namen.

Grenzen: Der Index ist ein Unterrichtsobjekt ohne reale Personendaten. Er ersetzt keine Zugriffsrechte oder Datenschutzregeln für echte Lernprofile.

Python-Beispiel zum Ausprobieren:

def index_by_id(rows):
    result = {}
    for row in rows:
        key = row['id']
        if key in result:
            raise ValueError('duplicate id')
        result[key] = dict(row)
    return result
rows = [{'id':'p1','name':'Alex','points':12}, {'id':'p2','name':'Alex','points':15}, {'id':'p3','name':'Sam','points':9}]
assert len(index_by_id(rows)) == 3
assert len({r['name']: r for r in rows}) == 2

Verständnis prüfen

Offene Fragen mit Musterantwort. Es gibt keine automatische Bewertung.

Warum ist eine feste Listenposition keine gute dauerhafte ID?

Ein Sortieren oder Einfügen kann die Position ändern. Die Person selbst bleibt dieselbe; ihre Identität darf nicht von der aktuellen Reihenfolge abhängen.

Darf ein Name korrigiert werden, ohne neue ID?

Ja, wenn es derselbe Datensatz bleibt. Die ID bezeichnet Identität, der Name einen änderbaren Anzeigewert.

Wie wird nach allen Personen mit Namen Alex gesucht?

Über eine Zuordnung, die mehrere IDs pro Name zulässt, oder über eine Suche durch die Datensätze. Ein einzelner Wert pro Name verliert hier Information.

Typischer Fehler

Eine plausible Ausgabe beweist noch nicht, dass ein Algorithmus für alle Fälle korrekt ist.
