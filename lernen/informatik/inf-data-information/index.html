Datentypen

Datentypen legen fest, wie ein Wert gespeichert und verarbeitet wird: ganze Zahl, Kommazahl, Zeichenkette oder Wahrheitswert. Dieselbe Bitfolge bedeutet je nach Typ etwas anderes.

Arbeite mit einem kleinen Beispiel, formuliere den Ablauf eindeutig und prüfe ihn mit Gegenfällen.

Binärcodierung

Information wird mit zwei Zuständen, 0 und 1, dargestellt. Mit n Bits lassen sich 2 hoch n Werte codieren, mit einem Byte also 256.

Acht Bits haben 256 verschiedene Muster. Als vorzeichenlose ganze Zahl interpretiert, reichen sie von 0 bis 255; im 8-Bit-Zweierkomplement reichen sie von -128 bis 127. Dasselbe Muster kann in einer anderen Kodierung auch Text oder einen anderen Datentyp darstellen. Das Byte selbst legt die Interpretation nicht fest.

Datenqualität

Fehlende, veraltete oder verzerrte Daten führen zu falschen Schlüssen. Wer Personendaten nutzt, braucht einen klaren Zweck und muss sie schützen.

Ein Beispiel: Eine Umfrage nur unter Jugendlichen sagt wenig über die ganze Bevölkerung aus. Prüfe deshalb Herkunft, Aktualität und Auswahl der Daten.

Genauer betrachtet

Ein Bit unterscheidet zwei Zustände, ein Byte acht Bits und damit 256 Muster. Der gespeicherte Zustand enthält aber nicht automatisch die Bedeutung vorzeichenlose Zahl. Ein Dateiformat oder Datentyp legt fest, wie die Muster gelesen werden.

Im vorzeichenlosen Format sind die Stellenwerte 128, 64, 32, 16, 8, 4, 2 und 1 positiv. Im 8-Bit-Zweierkomplement hat das höchstwertige Bit dagegen den Stellenwert -128. So lassen sich negative Zahlen darstellen, ohne die Anzahl der Muster zu verändern.

Ein Byte kann ausserdem Teil eines Zeichencodes, einer Bildfarbe oder eines Maschinenbefehls sein. Die Behauptung Byte bedeutet immer 0 bis 255 ist daher nur als Beschreibung einer bestimmten Interpretation richtig.

Durchgerechnete Beispiele

Daten, Information und Codierung

Aufgabe: Unverändertes Byte: binär 11111111, hexadezimal FF. Interpretiere es zuerst als vorzeichenlose 8-Bit-Zahl und danach als 8-Bit-Zweierkomplement. Verwende anschliessend Python nur als Gegenprobe.

  1. Vorzeichenlos: 128 + 64 + 32 + 16 + 8 + 4 + 2 + 1 = 255.
  2. Zweierkomplement: -128 + 64 + 32 + 16 + 8 + 4 + 2 + 1 = -1.
  3. Beide Interpretationen verwenden dieselben acht Bits. Nicht der Speicherinhalt wurde verändert, sondern die vereinbarte Leseregel.
  4. Die Wertebereiche folgen aus den extremen Mustern: vorzeichenlos 00000000 bis 11111111 ergibt 0 bis 255; mit Vorzeichen 10000000 bis 01111111 ergibt -128 bis 127.

Ergebnis: FF ist als unsigned Byte 255 und als signed 8-Bit-Zweierkomplement -1. Der Datentyp ist Teil der fachlichen Antwort. Kontrolle: Der beigefügte Pythoncode liest exakt dieselbe Bytefolge mit signed=False und signed=True. Beide Sollwerte werden mit Assertions geprüft.

Grenzen: Nicht jede Sprache verwendet für jede Zahl acht Bits. Der Fall beschreibt bewusst einen festgelegten Bytevertrag.

Python-Beispiel zum Ausprobieren:

raw = bytes([255])
assert int.from_bytes(raw, 'big', signed=False) == 255
assert int.from_bytes(raw, 'big', signed=True) == -1
assert int.from_bytes(bytes([128]), 'big', signed=True) == -128

Verständnis prüfen

Offene Fragen mit Musterantwort aus der KI-Prüfung. Es gibt keine automatische Bewertung.

Was ist binär 10000000 ohne Vorzeichen?

128. Im 8-Bit-Zweierkomplement ist dasselbe Muster dagegen -128.

Wie viele Muster gibt es nach dem Wechsel der Interpretation?

Weiterhin 256. Die Interpretation verteilt nur andere Bedeutungen auf die vorhandenen Muster.

Kann FF allein ein gültiges UTF-8-Zeichen sein?

Nein. UTF-8 hat eigene Regeln für zulassige Bytefolgen; ein beliebiges Byte ist nicht automatisch ein lesbares Zeichen.
