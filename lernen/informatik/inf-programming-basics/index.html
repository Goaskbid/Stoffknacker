Programme schreiben

Beim Nachverfolgen notiert man nach jeder Anweisung die Werte der Variablen. So sieht man, was das Programm tatsächlich tut.

Arbeite mit einem kleinen Beispiel, formuliere den Ablauf eindeutig und prüfe ihn mit Gegenfällen.

Testfälle

Ein Testfall legt Eingabe und erwartete Ausgabe fest. Gute Tests prüfen den Normalfall, Grenzfälle wie 0 oder eine leere Liste und ungültige Eingaben.

Ein Beispiel: Für eine Funktion, die den Durchschnitt berechnet, testet man eine normale Liste, eine leere Liste und negative Zahlen. So zeigen sich Fehler, bevor andere das Programm nutzen.

Fehlersuche

Syntaxfehler verletzen die Schreibregeln einer Sprache. Laufzeitfehler entstehen erst bei der Ausführung, etwa eine Division durch null. Logikfehler liefern ein fachlich falsches Resultat, obwohl das Programm läuft. Fehlersuche verwendet Fehlermeldungen, Zwischenwerte sowie Tests für Normal-, Rand- und Fehlerfälle; keine einzelne Methode findet alle Fehler.

Logische Fehler sind schwieriger, weil das Programm läuft, aber ein falsches Ergebnis liefert. Kleine, gezielte Tests helfen, sie Schritt für Schritt einzugrenzen.

Anwendung, Transfer

Zum Abschluss überträgst du die drei Kernbereiche auf eine neue Situation. Eine gute Lösung nennt Ausgangslage, Vorgehen, Ergebnis und Kontrolle.

Entwirf eine kleine digitale Lösung und begründe Datenmodell, Ablauf, Tests und Schutzmassnahmen. Die Begründung muss zeigen, warum das Vorgehen zur Frage passt.

Genauer betrachtet

Syntaxfehler betreffen die Schreibregeln der Sprache. Laufzeitausnahmen entstehen während einer zulässig geschriebenen Ausführung. Logikfehler verletzen die fachliche Spezifikation, ohne dass die Laufzeit zwingend eine Ausnahme meldet.

Ein Testfall besteht aus Eingabe und erwartetem Verhalten. Für Tarifgrenzen sind die Werte unmittelbar vor und auf der Grenze besonders wichtig. Nur einen Erwachsenen zu testen sagt wenig darüber aus, ob ein Jugendtarif korrekt abgegrenzt ist.

Auch Datentypen gehören in den Vertrag. Python behandelt bool als Untertyp von int. Wer nur isinstance(age, int) verwendet, akzeptiert deshalb unter Umständen True als Alter. Im folgenden bewusst engen Vertrag sind ausschliesslich echte ganzzahlige Alterswerte zugelassen.

Durchgerechnete Beispiele

Programmieren: Variablen, Bedingungen und Schleifen

Aufgabe: Fiktiver Tarif: unter 6 Jahren kostenlos, von 6 bis einschliesslich 17 CHF 8, ab 18 CHF 12. Zulässige Eingabe ist eine ganze Zahl von 0 bis 120. Texte, Wahrheitswerte und Werte ausserhalb des Bereichs werden abgewiesen.

  1. Schreibe zuerst die Grenztests: 5 ergibt 0; 6 ergibt 8; 17 ergibt 8; 18 ergibt 12. Diese Paare erkennen eine um eins verschobene Grenze.
  2. Prüfe den Eingabevertrag vor der Tarifentscheidung. Der Text 17 wird hier nicht stillschweigend umgewandelt. Eine Benutzeroberfläche könnte eine gesonderte, klar definierte Umwandlung anbieten.
  3. Verwende eine vollständige if/elif/else-Kette. Dann erreicht jeder zulässige Wert genau einen Tarifzweig.
  4. Teste -1, 121 und True als unzulässige Eingaben. Für diese Werte ist die richtige Reaktion nicht irgendein Tarif, sondern die vereinbarte Fehlermeldung.

Ergebnis: Die Tarifregel ist durch Eingabevertrag und Grenztests nachvollziehbar. Ein fehlerfrei laufendes Programm allein beweist noch keine fachliche Richtigkeit. Kontrolle: Der Code prüft die vier Grenzen sowie zwei weitere gültige Werte. Im separaten Testlauf werden die vorgesehenen Fehlerfälle tatsächlich aufgerufen.

Grenzen: Die Altersgrenzen sind ein erfundener Eintrittstarif. Sie beschreiben keine gesetzliche Altersdefinition oder reale Schule.

Python-Beispiel zum Ausprobieren:

def ticket(age):
    if type(age) is not int or not 0 <= age <= 120:
        raise ValueError('invalid age')
    if age < 6:
        return 0
    elif age < 18:
        return 8
    else:
        return 12
assert [ticket(x) for x in (0, 5, 6, 17, 18, 120)] == [0, 0, 8, 8, 12, 12]

Verständnis prüfen

Offene Fragen mit Musterantwort. Es gibt keine automatische Bewertung.

Ist if alter < 18 richtig für den Erwachsenentarif?

Nicht als Erwachsenenbedingung Die Spezifikation setzt den Erwachsenentarif ab 18 an. Entscheidend ist die Verbindung von Bedingung und zugewiesenem Preis.

Warum ist ein vollständiges else relevant?

Es deckt den verbleibenden Bereich ab. Ohne else und ohne zutreffende Bedingung kann eine Verzweigung auch keinen Zweig ausführen.

Welcher Fehler bleibt bei ausschliesslichem Test age=30 verborgen?

Eine falsche Grenze zwischen 17 und 18 oder zwischen 5 und 6. Ein Normalfall prüft nicht automatisch die Randfälle.
